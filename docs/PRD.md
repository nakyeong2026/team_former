# PRD: 팀 프로젝트를 위한 팀 편성 웹 앱

근거: 중간 과제 공고(10/16), 시연 동영상 https://youtu.be/ti-mDlKlfqg

## 1. 목표

학생(명단 CSV의 가상 학생)이 스스로 팀에 지원하고 팀원의 투표로 팀을 꾸린다. 모집을 마감한 뒤 남은 학생은 AI가 배정안을 내고, 앱이 그 배정안을 규칙으로 검사해 통과한 것만 관리자가 확정한다.

## 2. 사용자

| 사용자 | 로그인 | 하는 일 |
|---|---|---|
| 학생 | 학번 + 비밀번호(모두 1234) | 팀 목록·팀원·역할 보기, 팀에 지원, 내 팀에 들어온 지원에 찬성·거부 |
| 관리자 | `admin` + `ADMIN_PASSWORD` | 명단 CSV와 팀 수로 처음 상태 만들기, 모집 마감, AI 배정, 배정안 확정 |

- 관리자 계정은 앱이 시작할 때 `ADMIN_PASSWORD`로 만들거나 비밀번호를 갱신한다. 명단을 다시 올려도 남는다.
- 비밀번호는 해시(PBKDF2-SHA256, 학생마다 다른 솔트)로만 저장한다.

## 3. 규칙

### 3.1 팀
- 역할 6개: 기획자, 웹 프로그래머, 프론트엔드 디자이너, 테스터, 보고서 작성자, 발표자. 학생마다 주 역할 1개, 보조 역할 0~2개.
- 확정한 팀은 모두 2~4명.
- 한 팀에 주 역할이 같은 학생은 1명까지.
- 모든 팀에 기획자와 웹 프로그래머를 맡을 학생이 서로 다른 사람으로 1명씩(주 역할이나 보조 역할).

### 3.2 지원과 투표
| 상황 | 결과 |
|---|---|
| 빈 팀에 지원 | 바로 승인 |
| 팀원이 있는 팀에 지원 | 대기. 그 때의 팀원 모두가 투표 |
| 모든 팀원 찬성 | 승인 직전에 규칙(정원, 주 역할 중복, 필수 포함 역할 자리)을 다시 검사해 통과하면 승인, 아니면 거절 |
| 한 명이라도 거부 | 바로 거절 |
| 막힘(접수하지 않음) | 모집 마감, 이미 팀이 있음, 결과를 기다리는 지원이 있음, 팀이 꽉 참, 같은 주 역할의 팀원이 있음, 필수 포함 역할 자리가 모자람 |

- 필수 포함 역할 자리: 지원자가 들어간 뒤 남는 자리 수 < 그 팀이 아직 채우지 못한 필수 역할 수이면 막는다. 한 학생이 기획자와 웹 프로그래머를 둘 다 할 수 있어도 하나로만 센다(최대 매칭).
- 투표는 바꿀 수 없다.

### 3.3 마감과 배정
1. 마감하면 대기 중인 지원은 거절, 1명뿐인 팀의 학생은 팀에서 빠진다.
2. 규칙을 지키는 배정이 아예 없으면 AI를 부르지 않고 "규칙을 지키는 배정이 없음"과 이유를 보여 준다.
3. AI 배정: 1차 → 2차 → 3차 모델. 모델마다 부른 때부터 120초가 지나면 끊는다. 빈 응답, 오류, 형식 오류, 검사 불통과도 실패로 보고 다음 모델로 넘어간다.
4. 검사 다섯 가지: 팀이 없는 학생이 빠짐없이 배정, 한 학생은 한 팀에만, 모든 팀 2~4명, 주 역할 중복 없음, 필수 포함 역할 충족.
5. 3차 모델까지 실패하면 앱이 모든 경우를 따져(백트래킹) 검사를 통과하는 배정을 찾는다.
6. 검사를 통과한 배정안만 관리자에게 보여 주고, 확정하면 DB에 저장한다(이미 팀에 있는 학생은 옮기지 않음).

## 4. 화면

- 로그인, 학생 화면, 관리자 화면. 화면 요소의 Streamlit `key`는 공고 2.7절 표를 그대로 쓴다(`login_student_no`, `login_password`, `login_submit`, `whoami`, `result`, `team_N`, `apply_N`, `vote_yes_{학번}`, `vote_no_{학번}`, `admin_roster_file`, `admin_team_count`, `admin_start`, `admin_close`, `unassigned`, `admin_assign`, `assign_status`, `admin_confirm`).
- `result`의 안내는 "승인", "대기", "거절", "막힘" 가운데 하나로 시작한다.
- 다른 사람의 변경은 `st.fragment(run_every=5)`로 바뀐 부분만 5초마다 다시 그린다.
- 지원 단추는 이미 팀이 있거나, 결과를 기다리는 지원이 있거나, 마감되었으면 비활성화한다. 이미 투표한 지원은 단추 대신 "내 투표: 찬성"을 보여 준다.
- AI 배정 중에는 `assign_status`에 몇 차 모델의 응답을 몇 초째 기다리는지 보여 준다.

## 5. 데이터

Supabase(Postgres)의 `tf_` 테이블(`schema.sql`). 로컬에서 `DATABASE_URL`이 없으면 같은 스키마를 SQLite로 만든다.

## 6. 비밀 값

`OPENROUTER_API_KEY`, `DATABASE_URL`, `ADMIN_PASSWORD`. 로컬은 `.env`, 배포는 Streamlit Secrets. 코드와 화면에 값을 쓰지 않는다.

## 7. 범위 밖

구글 로그인(채점자가 여러 학생으로 로그인할 수 없음), 학생이 역할을 바꾸는 기능.
