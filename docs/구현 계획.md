# 구현 계획

PRD(`docs/PRD.md`)를 아래 순서로 만든다. 단계마다 pytest로 확인하고 나서 다음 단계로 간다.

## 1. 구조

화면 코드와 규칙·DB 로직을 나눠, 로직은 화면 없이 pytest로 시험한다.

| 파일 | 하는 일 |
|---|---|
| `rules.py` | 순수 규칙: 필수 포함 역할(최대 매칭), 지원·승인 직전 검사(`join_problem`), 배정안 검사 다섯 가지(`validate_plan`), 앱 자체 배정(`find_assignment`, 백트래킹), 배정이 없을 때의 이유(`diagnose`) |
| `db.py` | Postgres/SQLite 연결 하나를 만들어 다시 씀. `schema.sql`을 그대로 실행. 트랜잭션(`write`)과 읽기(`read`), 끊긴 연결 재접속, 유일성 제약 위반을 `Conflict`로 바꿈 |
| `service.py` | 명단 올리기, 로그인, 지원, 투표, 마감, 배정안 저장·확정. 결과는 "승인/대기/거절/막힘: 이유" |
| `ai_assign.py` | OpenRouter 호출, 모델마다 120초 전체 대기 제한, 1→2→3차 모델, 응답 해석, 실패 시 앱 자체 배정 |
| `streamlit_app.py` | 로그인·학생·관리자 화면, 2.7절의 key, `st.fragment(run_every=5)` |
| `settings.py` | 환경 변수 → `.env` → Streamlit Secrets 순서로 비밀 값을 읽음 |
| `auth.py` | PBKDF2-SHA256 비밀번호 해시 |
| `schema.sql` | `tf_` 테이블과 제약(앱이 시작할 때 이 파일을 실행) |

## 2. 단계

1. 규칙 모듈과 단위 시험(`tests/test_rules.py`)
2. DB 스키마(`schema.sql`)와 연결 계층. 로컬은 SQLite로 개발
3. 서비스 계층과 연습용 시나리오 3개 재현 시험(`tests/test_scenarios.py`). 기대 결과의 첫 단어가 단계마다 같아야 함
4. AI 배정: 가짜 호출 함수로 1→2→3차 전환, 검사 불통과, 120초 제한, 앱 자체 배정을 시험(`tests/test_ai_assign.py`)
5. Streamlit 화면. 내장 브라우저에서 key로 단추를 눌러 연습용 시나리오 3개를 처음부터 끝까지 실행
6. 실제 무료 모델로 AI 배정 시험(하루 50회 한도를 아껴 씀). 응답한 모델, 몇 차 모델인지, 걸린 시간을 `tf_ai_logs`에 기록
7. Supabase 연결(`DATABASE_URL`), 깃허브 비공개 저장소, Streamlit Community Cloud 배포, Secrets 설정
8. DB 일시정지 막기: 외부 예약 서비스(예: GitHub Actions 예약 실행)로 매일 DB에 질의
9. README.md 작성(배포 주소, 고른 해결 방법, 모델 3개, 실패 사례·클로드 오류 사례·개선점과 근거)

## 3. 3장 표에서 고른 해결

| 기능 | 고른 해결 | 구현 |
|---|---|---|
| 다른 사람의 변경 보기 | 어려운 해결 | `st.fragment(run_every=5)` |
| 필수 포함 역할을 지킬 수 없는 팀 | 어려운 해결 | 지원할 때 `join_problem`이 자리 수를 따져 막음 |
| 같은 팀에 대기 중인 지원이 여럿 | 어려운 해결 | 모든 팀원이 찬성한 순간 `join_problem`으로 다시 검사 |
| 마지막 자리에 두 명이 동시에 들어감 | 어려운 해결 | `tf_members`의 (team_id, slot_no) 기본 키와 student_id 유일성 제약 |
| AI 응답이 늦을 때 | 어려운 해결 | 별도 스레드에서 호출하고 부른 때부터 120초가 지나면 끊음 |
| 3차 모델까지 실패 | 어려운 해결 | 백트래킹으로 다섯 가지 검사를 통과하는 배정을 끝까지 찾음 |
| AI 대기 중 화면 | 어려운 해결 | `assign_status`에 "N차 모델(…)의 응답을 기다리는 중… M초 지남" |
| DB 일시정지 막기 | 어려운 해결(배포 단계에서) | 외부 예약 서비스로 매일 질의 |

## 4. 결정한 것

- 팀 번호: `tf_teams.id`를 팀 번호로 쓴다(명단을 올릴 때마다 1부터 다시 만듦). `team_1`의 1과 시나리오의 팀1이 같다.
- 한 학생의 대기 지원은 하나뿐: `tf_applications(student_id) WHERE status='대기'` 부분 유일 인덱스로 DB에서도 막는다.
- 연결: Streamlit의 `st.cache_resource`로 연결 하나를 모든 사용자가 같이 쓰고, `threading.Lock`으로 한 번에 한 요청만 처리한다. 그래서 같은 프로세스 안에서는 검사와 기록 사이에 다른 요청이 끼어들지 않는다. 여러 프로세스를 대비해 Postgres에서는 팀 행을 `FOR UPDATE`로 잠근다.
- 확정 전 배정안은 `tf_settings`의 `proposal`에 저장해, 관리자 화면이 다시 연결되어도 사라지지 않게 한다.
- AI 모델은 제공자가 서로 다른 무료 모델 3개(`ai_assign.MODELS`). 무료 자동 라우터 `openrouter/free`는 쓰지 않는다.
